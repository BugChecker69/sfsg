I-BO（アイボー）です。

約半年前、秋葉原の中古ショップにて **9,800円** で購入した初代 **Microsoft Surface Go**。

Windows 10 のサポート終了やスペック面（Pentium Gold 4415Y）を考慮し、軽量な Linux への OS 載せ替えを試みたものの、**「ISO を書き込んだ USB メモリからブートできず、何度やっても内蔵ストレージの Windows 10 が起動してしまう」** という最初の壁にぶつかり、うまく進められず半年間放置していました。

今回、改めて **Fedora Linux**（現環境：Fedora Linux 45 / GNOME Shell 51.1）の導入に再挑戦。UEFI 画面からの直接起動には手こずったものの、**「一度 Windows 10 を起動させた状態から、回復オプション（トラブルシューティング ＞ メディアを使用してリカバリ / UEFI 起動指定）を経由する」** という手順で突破口を開き、無事に USB からのブートとインストール、さらにハードウェアの最適化まで完了させてみました。

---

### システム・ハードウェア環境（構築完了後）

- **デバイス**：Microsoft Surface Go（第1世代）
- **OS**：Fedora Linux 45 (Workstation / GNOME)
- **カーネル**：`Linux 7.2.15-1.surface.fc45.x86_64`（`linux-surface` 専用カーネル）
- **ファームウェア (UEFI)**：`1.0.19`（`fwupdmgr` にて最新化済み）

---

### 一番手こずったポイント：USB メモリからブートできない問題

今回の復活劇で最も時間を取られたのが、Fedora のインストール ISO を書き込んだ USB メモリを認識させ、起動（ブート）させる工程でした。

#### 発生していた現象

- USB メモリを挿して電源を入れても、USB 側のインストーラーではなく、毎回内蔵 SSD の **Windows 10 がそのまま立ち上がってしまう**。
- Surface UEFI のメニュー（`Boot configuration`）から起動順序を変更しようとしたり、一般的な手順として語られる「`USB Storage` の項目を左へスワイプして即時ブートする操作」を試したりしても、この端末では機能せず、OS の載せ替えそのものに着手できない状態が続いていました。

#### 突破口と解決のポイント

UEFI 画面単体からのブート切り替えを諦め、**Windows 10 側の「高度なスタートアップ（回復オプション）」から外部メディア起動を強制指定する** ことで解決しました。

1. **Windows 起動後の「トラブルシューティング（回復オプション）」からのブート強制**  
   一旦そのまま Windows 10 を立ち上げ、「設定」＞「更新とセキュリティ」＞「回復」の **「PC の起動をカスタマイズする（今すぐ再起動）」**（または `Shift` キーを押しながら再起動）を実行。  
   青いオプション画面で **「トラブルシューティング」**（または「デバイスの使用」）に進み、メディアを使用してリカバリ・UEFI からの起動対象として USB デバイスを指定したことで、ようやく Fedora のライブ環境が立ち上がりました。

2. **前提条件の整備（セキュアブート・書き込み形式・USB-C 接続）**  
   - **セキュアブート（Secure Boot）の無効化**：UEFI の `Security` 項目で `Disabled`（無効）へ変更し、Linux ブートローダーやカスタムカーネルがブロックされない状態にしておきます。
   - **GPT / UEFI 形式での ISO 書き込み**：古い MBR 形式ではなく、**Fedora Media Writer** や **Rufus（GPT / UEFI モード指定）** を用いて UEFI ブート可能な形式で USB メモリを作成しました。
   - **USB-C 変換の確保**：初代 Surface Go は USB-C ポートが1つのみのため、UEFI 起動時にも確実に認識される変換アダプタ経由で接続しています。

---

### ハードウェア最適化の試行と解決策

#### 1. 専用カーネル（`linux-surface`）の導入とファームウェア更新

汎用 Linux カーネルのままではタッチスクリーン、カメラ、バッテリー管理、電源制御などが不安定になるため、Surface シリーズ専用にパッチが当てられた `linux-surface` カーネルを導入しました。

- `linux-surface` 公式リポジトリの追加と `kernel-surface` / `iptsd` / `libwacom-surface` のインストール。
- `fwupdmgr` コマンドを使用して Microsoft 公式の最新 UEFI ファームウェア（`1.0.19`）へ更新。

#### 2. 電源管理（サスペンド復帰不能・電源断）の対策

Surface Go と Linux の組み合わせでは、モダンスタンバイ（S0ix）との相性により「スリープに入ると復帰できなくなる」「シャットダウン後も内部通電が残る」という既知のトラブルが発生しやすくなります。

- **電源ボタンの挙動変更**：「設定」＞「電源」から、電源ボタン押下時の動作をサスペンドではなく **「電源オフ」** に固定し、誤操作によるスリープ落ちを防止。
- **電源断の確実化**：GUI からの電源オフで通電が切れない場合は `sudo systemctl poweroff -f` を使用し、必要に応じてカーネル起動オプションへ `reboot=acpi` を付与して ACPI 制御を安定化させています。

---

### デスクトップ操作性のカスタマイズ

Windows からの移行でも違和感なく使えるよう、クリップボード履歴ランチャーを導入しました。

- **クリップボード履歴（`[Super] + V`）の実装**  
  Flatpak 版 **Extension Manager**（`com.mattjakeman.ExtensionManager`）を導入し、GNOME 拡張機能 **「Clipboard Indicator」** をインストール。  
  OS 標準の `Super + V`（通知リストの表示）のキー割り当てを解除し、Clipboard Indicator のメニュー呼び出しに `Super + V` を割り当てました。

---

半年間「USB ブートすらできず Windows 10 が立ち上がってしまう」状態で眠っていた 9,800円の初代 Surface Go でしたが、**Windows 側の回復オプション経由で USB メディア起動を強制する** ことで突破口を開き、Fedora の導入に成功しました。さらに **`linux-surface` カーネルによるハードウェア最適化** を行うことで、軽量かつ実用的なサブ機として見事に復活しました。
